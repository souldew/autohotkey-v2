経緯

もともとは、一定の速さで動かし、加速キーを押している間だけ速くする実装（legacy-accel-keys）にしていた。しかし、この方式ではドラッグがしづらかった。

  • 一定の速さでは、ドラッグ中に細かく位置を合わせられなかった
  • 加速・減速キーに Shift・Ctrl を使っていたので、ドラッグ中に修飾キーとして押したいときにぶつかった

そこで、QMK の Mouse Keys の既定の動き方（Accelerated: キーを押し続けるほど速くなる）を取り入れた。押し始めは遅いので細かく合わせられ、加速・減速キーが要らないので Shift・Ctrl を修飾キーとして使える。設定の値は、よく参照される配列の Miryoku に合わせた。

ただ、Miryoku の最高速（約 3000px/秒）は速すぎて目で追えないので、そのままは採用しない。もとの実装の最高速（加速キーを押したときの 36px/ループ）を目安にした。カーソルを次のディスプレイへ移す機能を入れるなら、長い距離を動かす速さはそこまで要らない。そのため、加速しても目で追える 28px（16ms あたり、約 1750px/秒）をいったん採用した。

速さの比較

ループの間隔（legacy-accel-keys・linear-ramp）

移動キーを押し続けたときの、その時点の速さ。凡例を押すと線を出し入れできる。QMK 方式は押した瞬間だけ 8px 動くが、1 回きりなのでこのグラフには出ない。

動いた距離の比較

押し始めからカーソルが動いた合計の距離。短く押したときにどれだけ動くかで、細かい位置合わせのしやすさが分かる。速さのグラフと同じ線を表示する。

QMK の Accelerated の計算

QMK の quantum/mousekey.c の move_unit（速度切り替えキーを押していないとき）。repeat は押し始めから送ったレポートの数で、押した瞬間が 0、直後が 1、以降 MOUSEKEY_INTERVAL ごとに 1 ずつ増える。

if repeat == 0:            unit = MOUSEKEY_MOVE_DELTA
elif repeat >= TIME_TO_MAX: unit = MOUSEKEY_MOVE_DELTA * MAX_SPEED
else:                       unit = MOUSEKEY_MOVE_DELTA * MAX_SPEED * repeat / TIME_TO_MAX
unit = clamp(unit, 1, MOUSEKEY_MOVE_MAX)

Miryoku の値（MOVE_DELTA 8、MAX_SPEED 6、TIME_TO_MAX 64、INTERVAL 16ms）では、1 レポートの移動量が 16ms ごとに 0.75px ずつ増える。miryoku-max36・miryoku-max28 は、この傾きのまま MOUSEKEY_MOVE_MAX で上限だけを下げたもので、上限が低いほど早く最高速に届く。

  • 斜めに動くときは、縦・横それぞれ 181/256 倍（約 0.7 倍）にする（QMK の times_inv_sqrt2）
  • 1 レポート = 1px として扱う。実機の QMK は USB マウスとしての移動量なので、Windows のポインター速度の設定しだいで体感が少しずれる
  • AutoHotkey の Sleep は 10ms か 15.6ms に切り上げられるので、経過時間から送るべきレポート数を数え、遅れた分はまとめて動かす

参照: QMK の mousekey.c・miryoku_qmk の config.h・QMK の Mouse Keys

ホイール

ホイールも MM_WHEEL_PRESET の名前で選ぶ。今は qmk-default（2026-11-19〜）で、送る間隔（80ms）は変えずに、押し続けるほど 1 回に送るノッチ数を増やす。QMK の wheel_unit の計算式に QMK の既定値をそのまま入れたもの。

  • 押した瞬間に 1 ノッチ。100ms 待ってから 80ms ごとに繰り返し、約 0.8 秒までは 1 回 1 ノッチ（毎秒 12.5）
  • そこから 0.4 秒ごとに 1 回のノッチ数が 1 ずつ増え、約 3.2 秒で 1 回 8 ノッチ（毎秒 100）になる
  • 複数ノッチは 1 回のホイールイベントでまとめて送る

Miryoku は繰り返しまでの待ち時間（MOUSEKEY_WHEEL_DELAY）を 0 にしていて、単押しでも 2 ノッチ送る。それまでの実装より単押しのスクロール量が増えるので、QMK の既定の 100ms のほうを採用した（miryoku もプリセットに残している）。

前のプリセット linear-interval は、1 ノッチずつ送り、送る間隔を 1 秒かけて 100ms から 25ms まで縮めていた（毎秒 10 → 40）。比較は mouse-speed-presets.md。

ホイールの速さの比較

スクロールキーを押し続けたときの、その時点の速さ。押した瞬間の 1 回目（qmk-default は 1 ノッチ、miryoku は続けて 2 ノッチ）はこのグラフには出ない。qmk-default は最初の 100ms は繰り返さないので線が無い。

送ったノッチ数の比較

押し始めから送ったノッチ数の合計。1 ノッチで何行スクロールするかは Windows の設定（既定は 3 行）で決まる。速さのグラフと同じ線を表示する。
